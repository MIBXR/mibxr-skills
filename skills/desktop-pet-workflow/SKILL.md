# 桌宠制作与修复

把用户认可的角色基准、正式图集与展示预览分别记录，保留可继续创作的资料。格式由当前目标应用决定，角色比例与画风由本次用户要求决定。

## 定位任务

先从实际作品与应用记录确定目标、最新成品和授权范围。文件修改时间或同名记录不足以确认版本。

- 新制作：从参考确定外形、关键特征与主要动作；缺少会改变角色身份的决策时再提问。
- 局部修复：圈定动作行、帧与允许改变的特征，读[动作修复](references/animation-repair.md)。
- 迁移或交付：保留正式图片，读[交付与导入](references/delivery.md)，按目标应用支持的方式操作。
- 整理作品与版本：读[作品与版本发布](references/repository-and-release.md)，先确认展示与保存的定位，再确定资料、Git 提交及 Release 的组织。

执行生图、修图或应用导入时使用当前环境提供的工具。技能本身不提供生成服务、认证或安装接口。

## 制作与修复

1. 读取目标应用的实际图集格式与播放规则；预览节奏和真实应用表现分别看待。
2. 以认可形象对照整组动作，保留有意的步态、跳跃与局部运动。
3. 从交付图片检查显示尺寸、放大细节、循环衔接与状态切换；结构合法不能代替视觉判断。
4. 保留前后图集时，可用技能内可选的 `scripts/compare_atlas.py` 检查授权行以外的像素。它只回答像素是否变化，不判断好看与否。
5. 上传或导入后回读目标应用结果；不能观察真实播放时如实说明。

比较脚本的参数来自实际图集，行号从 1 开始：

```sh
python scripts/compare_atlas.py --before before.png --after after.png --columns 8 --rows 11 --allow-rows 4
```

路径相对于本技能目录，脚本需要 Pillow。一次性处理工具与报告留在任务工作区。

## 保存作品

作品仓库保存制作来源、参考、提示词、高清原稿和成品，README 优先展示作品。用户明确需要维护加工项目时，才加入处理配方、依赖和自动检查。制作中使用某个工具，不意味着要把工具和运行报告提交到作品仓库。

通用方法放技能，角色专属思路放作品记录，账号与机器环境留在目标环境。交付时说明实际改动和完成情况；复制、下载、上传成功与应用中可见是不同的完成条件。
