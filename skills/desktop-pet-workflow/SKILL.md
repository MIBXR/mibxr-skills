# 桌宠制作与交付

把用户认可的形象变成有明确含义的小动作，同时用 Git 留下参考、实际提示词、高清原稿与成品，让下一次修改有据可依。需要宠物网站时，把角色、动作与下载安装组织成可以欣赏和互动的页面；宠物、网站与应用导入按本次范围分别完成。

## 先找到本次工作的依据

读取当前作品、相关应用记录和最近的用户决定，确认目标宠物、正式图集、名称与允许修改的部分。涉及应用操作时再确认当前启用状态；制作网站时同时读取现有源码、页面和下载素材。文件名、修改时间、旧导出包和先前成功消息只能帮助定位，不能单独证明哪个版本最新。

把角色固定特征与本次动作要求分开：外形、构图、服装、眼睛、配饰、尾巴和画风来自当前参考；动哪些部位、表达什么情绪、是否使用道具来自动作设计。沿用用户确认的称呼，对形象有歧义时对照参考，不凭印象补写。

缺少会改变角色身份、交付范围或既有作品的决定时提问。用户要求先评审，就先给问题与图示；已批准的方案继续完成。旧记忆中的画风、尺寸、名字和安装路径都需要结合当前状态判断。

## 从制作开始使用 Git

新建宠物或宠物网站时就建立或接入 Git，不等到最终交付再保存一次。先检查现有仓库、远端和未提交改动；已有仓库沿用，新作品在确认的作品目录初始化。只咨询、只看预览或只导入现有宠物的任务不因此创建仓库。

宠物制作与网站制作都先读[作品与版本](references/repository-and-release.md)中的完整目录与提交规则。常用顶层是 `pets/<pet-name>/` 和可选的 `site/`：前者放创作来源、参考、实际提示词、高清素材与解包成品，后者放网站完整源码及其资源。复用既有结构，不在 `site/` 里再建嵌套仓库。

有意义的创作进展及时提交，正式宠物版本分别提交并对应标签和 Release；网站更新可以单独提交。历史资料按实际提供的版本导入，不补造缺失过程。推送、仓库可见性及线上部署遵循当前授权，已明确的决定不重复询问。

## 从形象走到动作

**先看安装格式。** 读取目标应用当前的图集布局、有效帧数、透明要求和状态含义，再设计动作。应用里名为 `running` 的状态可能表示正在工作；左右移动与工作状态要按实际含义分别设计。

**主动联网研究角色。** 决定新动作前，搜索角色特点、官方设定、同人社区、招牌动作、癖好，以及体现性格的神情和小动作。区分官方事实、社区解读与自己的创意建议，保存实际采用的来源。把研究转化为角色特有的动作表达，避免每款宠物都套用同一组通用姿态；原创角色以用户设定为事实依据，网络资料用于寻找灵感。

**先确认动作方案，再确认关键设计图。** 新建、增加或重新设计动作时，先逐项询问用户希望如何表现，并给出结合角色特点的建议。协议状态定义触发和用途，视觉表现可作角色化发挥。覆盖全部待制作动作及注视设计，取得用户对各项方案的确认后，先生成一版关键设计图并展示；用户确认图中形象与动作后，才制作完整动作帧和正式图集。两个确认节点的具体内容见[角色与动作制作](references/creation.md)。

尚未确认时停留在对应阶段，不以未回复或对整体制作任务的授权代替内容确认。已有明确确认的方案可沿用；保持动作含义和设计的局部对齐、调色或边缘修复按原修复范围完成。改动动作表达或增加新设计时，先确认受影响的方案与设计图。

**先固定角色，再展开动作。** 从已认可的主形象或待机中确定比例、配色、线条、眼睛结构与关键配饰。先把一个完整动作家族做一致，再扩展其他动作。单张图好看不代表放在一起还是同一个角色。

**每个动作有明确的故事。** 挥手有抬手、回应与回位，跳跃有蓄力、离地和落地，工作有清楚的行为对象，等待有期待回应的神情。用角色适合的小动作表达状态；道具与辅助符号由当前设计决定。

**保存实际制作材料。** 在生成时留下提示词、参考作用与生成原稿。最终图集可能经过选帧、透明处理和位置调整，高清原稿也应保留。回顾性的动作说明与原始提示词分别标明，缺失资料不补造成真实调用。

## 修改时守住已经认可的部分

先分清位置、形状、颜色和动作表达的问题。位置偏移可以对齐，压扁的脸需要处理形状；统一色彩时按材质对照参考，避免连带改变轮廓和透明度。

对齐使用躯干、胸前饰物、衣服接缝等稳定部位。手臂和发尾会改变整体轮廓，按每帧外轮廓重新居中容易制造抽动。稳定需要静止的部分，同时保留有意的眨眼、挥手、步态与腾空。

按整组检查固定特征与配色，再看末帧接首帧、待机到动作再回待机，以及分段注视的接缝。发现旧原稿覆盖了较新的修复时，先恢复正确来源，再继续当前修改。

## 成品怎么看

预览从最终编码的正式图集中取得，先按实际显示大小看动作，再放大检查眼睛、边缘和接缝。高清设计稿可以另外展示，但应说明它与安装成品的区别。

需要全部动作展示时，逐项提供 GIF，并覆盖所有注视方向。动图、结构检查和真实应用播放分别回答不同问题：图集合法不代表没有抖动；预览播放正常也不代表应用会以同样节奏触发。

设计帧数超过应用格式时，先核实限制，再让用户选择兼容成品与完整设计稿的安排。素材能改善的部分实际完成；由应用控制的停留、循环或触发行为单独说明。

## 保存作品

作品仓库保存创作来源、参考、提示词、高清原稿和解包成品，README 展示形象、全部动作、来源和下载。检查是制作过程中做的事，不因此向作品仓库添加检查体系。只有用户明确要维护加工项目时，才组织可复用程序与依赖。

## 宠物展示网站

网站围绕当前宠物组织：角色介绍说明款式与创作特点，动作剧场能体验全部实际动作与注视方向，下载区用对应角色预览说明安装对象。导航、快捷跳转和高亮与这些区域对应，文案使用自然中文和用户确认的角色称呼。

网站素材也可以通过角色网络研究寻找：从官方设定、招牌动作、惯用道具、角色场景和同人社区中提出素材候选，说明来源和用途。首次制作或改变布局时，给出排版建议并询问用户选择，最终版式由用户确认后实施；已有认可的版式继续沿用。具体做法见[宠物网站设计](references/pet-site-design.md)与[网站素材](references/pet-site-assets.md)。

参考网站时同时看外观和行为；保留已认可的人物比例、页面布局、装饰与交互。网页可以使用自己的高清图片和动作资源，下载仍指向真实便携成品。区分源像素与放大画布，透明处理与边缘去染色分别解决。

首屏、动作剧场与安装卡片分别管理动画状态。操作反馈等待素材加载完成后计时，复制成功才给成功反馈，并遵守暂停和减少动态效果；兼顾触屏、键盘、窄屏、深浅色与用户主题扩展。

源码与运行素材一起纳入 `site/`。只整理源码就交付完整目录；更新宠物时按本次要求决定是否同步网页，不强制从 `pets/` 自动构建网站。README 同时展示真实网站截图，通用网站开发步骤无需另立技能。

## 完成当前任务

交付时对应本次任务说明结果：素材完成、版本已提交或推送、便携包可用、目标应用已更新、当前选择是否改变，以及网站源码已保存或已部署。只对实际读回或观察到的结果作完成声明。通用方法放技能，角色专属材料放作品，环境身份留在目标环境。
