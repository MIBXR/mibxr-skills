# 宠物网站的设计与交互

用于新建或改版宠物展示页、还原参考交互，以及排查布局或动画反馈的问题。先按[Git 作品仓库](repository-and-release.md)接入版本管理；宠物选择、网页素材与下载内容均以当前作品为准。

## 读懂参考

| 观察层面 | 要记住的行为 |
| --- | --- |
| 信息与版式 | 章节职责、标题层级、人物和文字比例、留白、卡片与装饰的关系。 |
| 默认状态 | 首屏是否自动待机，多个角色是否独立循环，尚未操作时页面呈现什么。 |
| 操作反馈 | 悬停、点击、复制、下载各触发什么，反馈结束后回到哪里。 |
| 定位与导航 | 快捷链接跳到哪个区域，是否识别并高亮选中的具体作品。 |
| 适配 | 触屏如何替代悬停，窄屏怎样缩放，暂停与减少动态效果如何表现。 |

源码解释机制，浏览器确认实际效果。缺失或过期的附件不能声称已阅读；可以使用确实保存的参考文件，并说明依据。

## 内容与视觉的关系

新网站的内容未定时，先明确介绍哪些作品、需要何种互动和下载方式，再提出少量风格方案。已有明确决定就以之为起点。

宠物网站重点组织以下内容，按实际作品和用户选择组合，不套用固定章节数量：

| 内容 | 设计要点 |
| --- | --- |
| 首屏与角色介绍 | 展示当前形象、款式和特点，保留清晰插画；需要默认动画时，各只宠物独立待机。 |
| 动作剧场 | 覆盖全部实际动作与注视方向，能选中明确的宠物和动作。中文名称对应状态含义，工作状态不能仅因接口名是 running 就写成跑步。 |
| 下载与安装 | 卡片显示对应宠物及预览，清楚区分复制 Agent 指令和直接取得 ZIP，说明是否会切换当前宠物。 |
| 来源与创作说明 | 给出实际角色和插画来源，链接制作资料；真实迭代过程按用户需要展示。 |

让导航与主要内容区域一一对应。介绍可以保持简短，把观看动作与安装引向各自区域；下载区需要突出时独立呈现，同时用角色缩略图或动态预览说明当前对象。

柔和背景、圆角卡片、轻微叠放、舒服的留白与克制动效适合亲切的宠物页面；它们是可选设计方向，具体颜色、标题、构图与装饰由当前角色和用户选择决定。

维护整体视觉规则：同级链接共享字重、下划线与装饰反馈，同类章节使用一致的留白和分割方式。某节取消特殊底色后，检查它是否需要恢复与其他章节相同的分割线。

对已认可的首屏比例、角色与装饰相对位置、窄屏缩放方式做局部调整。参考用于帮助判断，不让整个网站因一次局部改动重新设计。

## 自然且准确的文案

优先介绍角色特点、作品体验与操作结果。按钮使用用户能直接理解的词，例如“下载桌宠”“看看动作”；加工和验证术语留在需要解释的地方。

作品名称使用服装、构图或风格区分款式，版本号另列。物种、身体部件、配饰和动作以参考及用户称呼为准；用户修订一处后，检查其他介绍与说明中的同类表述。

原角色、参考插画、AI 辅助素材与网站制作分清来源。创作历程有真实记录且用户要展示时才写；缺少历史材料就介绍当前作品和创作思路，不编造修复日期与前后故事。

## 独立的动画状态

首屏、展示区和安装卡片各自拥有动作、帧位置、加载状态及回应状态。选择展示区的动作时，首屏可继续自己的待机；一张安装卡片回应时，不触发另一张卡片。

注视交互按当前图集的方向顺序映射页面坐标，明确左右与上下，实际查看分段接缝和整圈回环。触屏或键盘需要可达的替代入口；只有静态方向预览时就按其真实能力介绍。

短暂回应要有明确触发与结束：例如点击后招呼，复制成功后播放一次用户指定的完成动作，再恢复该区域的正常状态。回应动作的选择来自当前设计，不把某次项目的“挥手”或“跳跃”固定成通用要求。

等待素材加载完成后再开始回应计时，避免加载时间消耗掉整段动作。快速重复点击、动作尚未加载、复制失败以及回应期间切换标签时，反馈应与实际结果一致。

暂停与减少动态效果属于用户选择。无论自动待机、悬停还是操作回应，都按页面已定义的策略遵守该选择；必要的操作确认仍可用静态文字反馈。

## 跳转和响应式

快捷入口指向对应章节与具体作品，并用明确高亮帮助用户确认位置。链接若依赖悬停呈现反馈，同时考虑键盘焦点与触屏点击。

在桌面、布局开始变化的中间宽度以及典型窄屏查看。390 和 320 像素可作为窄屏样例，而非所有项目必须使用的断点。逐项检查星标、标签、按钮和叠放关系，避免用隐藏已经认可的元素掩盖拥挤。

浅色与深色都要看文字、边框、背景层次及透明图片边缘。支持系统主题和浏览器主题扩展，避免加入会屏蔽用户主题工具的锁定。共享背景、边框或布局修改后，复查相邻章节的一致性。
