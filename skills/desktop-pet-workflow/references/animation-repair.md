# 动作修复

用于已有动画出现抖动、比例、颜色、部件或时序问题的情况。先定位成品中的具体症状，再选择最小的有效修改。

## 建立比较对象

保留当前正式图集的副本，记录允许改动的动作与特征。使用最新认可的待机或指定参考，对照头部、脸部、躯干、底部落点、眼睛、配饰数量、线条和各材质颜色。

先看整组姿态，再循环播放。首帧正常可能掩盖中间帧变形；单组正常也可能在切换到待机时跳变。定位纯偏移、几何变形、色彩漂移和动作语义问题，避免用一种处理覆盖所有问题。

## 按症状处理

| 症状 | 判断与处理 |
| --- | --- |
| 挥手时全身抽动 | 对照躯干、胸前饰物、衣领等稳定区域。手臂、头发和飘带会改变整体包围盒，逐帧按外轮廓居中会制造漂移。纯位置问题可在工具规则与授权允许时使用不裁切的整数平移。 |
| 脸变扁、工作时头部变矮 | 先区分位置与形状。平移不能修复压扁，非等比拉伸会破坏脸型；确需调整尺度时使用整组一致比例，再与主形象对照。 |
| 发色、眼睛或服装忽深忽浅 | 按材质分别与认可参考比较。采用当前工具与授权允许的调色或重绘方法；纯调色保护 alpha、轮廓和几何。逐帧独立滤镜、整体降亮度都可能引入新的偏差。 |
| 道具随手漂移 | 区分固定道具外轮廓与需要运动的手指、手臂。以笔记本为例，盖板、铰链、底座固定，小手仍要有可见的敲击。 |
| 配饰数量或眼睛结构不一致 | 将当前角色的固定特征逐帧对照，特别留意重绘后的瞳孔、虹膜、眼白、耳饰、左右位置与连接关系。 |
| 等待、工作只剩机械摇摆 | 回到动作含义，用姿态、视线、手中对象和合适的辅助元素表达状态。机械移动整张图通常不能替代这种表达。 |
| 轮廓出现杂色边缘 | 将透明度问题与原背景颜色染入边缘的问题分开看，保护正常墨线、内部颜色和透明范围。 |

只处理授权区域；同时回看前次已修好的部位。需要重新生成时沿用最新身份参考，不让旧原稿重新带回已修好的眼睛、比例或颜色问题。

修复涉及改变动作表达、关键姿态或道具时，先转入[角色与动作制作](creation.md)，取得受影响方案与关键设计图的确认后再制作。仅恢复已认可设计的位置、颜色、轮廓等技术修复，按原修复范围继续。

## 保留有意的运动

站立挥手时固定躯干和落点，保留手臂动作；工作时固定道具，保留手部变化；跳跃保留腾空高度并回到起落基准；移动保留步态及适当的身体起伏。

稳定不能等同于冻结。检查小幅动作时同时在真实显示大小和放大尺寸下观察，确认修复后仍能看懂动作。

## 检查接缝与时序

- 动作内部的连续变化，以及末帧回到首帧。
- 待机 → 动作 → 待机的大小、颜色与落点。
- 跳跃起落、移动循环、固定道具与手部之间的关系。
- 方向组分段连接处，以及最后一个方向回到第一个方向。

预览从最终编码图集生成。用户要求分别看动作时，逐项提供 GIF；高清设计预览与实际安装预览分别说明。

当设计帧数多于安装格式，保留完整设计，另按用户选择制作兼容版本。眨眼变慢、工作状态提前结束或注视未触发时，读取当前应用的停留时间、循环和触发规则；历史诊断时长不能当作当前规则。

素材能改善的部分继续完成，应用控制的限制说明清楚。不能观察目标应用时，只报告已经确认的图像与预览结果。

## 判断有没有改到其他内容

必要时用当前环境的图像工具比较修复前后解码的 RGBA 像素，检查授权动作之外是否发生变化。PNG 压缩字节不同与画面像素不同是两回事；哈希不一致时先辨别原因。

结构检查回答尺寸、透明格与帧排列是否合规，像素比较回答哪些区域改变，视觉检查回答动作与形象是否自然，应用观察回答真实触发和节奏。根据本次修改选择需要的证据，不把一种结果代替另一种。

这些检查在任务工作区完成即可。独立复核只有在实际存在独立输入与评价时才能这样称呼；普通自检如实描述。
