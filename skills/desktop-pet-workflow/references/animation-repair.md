# 动作修复的判断依据

## 建立视觉基准

使用用户认可的待机或指定参考，记录头部和躯干比例、可见底部、关键配饰数量、材质配色与线条。基准用于对照，不把旧角色的服装、画风或比例推广给新角色。

先看整组接触表，再看循环播放。单帧满意仍可能出现颜色漂移、尺度变化或错误配饰。独立审核需要真实独立输入与评价，自检不能标成盲检。

## 按症状选择处理

| 症状 | 检查与处理 |
| --- | --- |
| 挥手时身体跳动 | 用躯干、胸前细节等稳定区域配准。手臂、头发和飘带改变整体包围盒，按整张轮廓居中可能制造抖动。单纯偏移优先采用不裁切的整数平移。 |
| 头部变扁、动作变小 | 区分落点与形状变化。平移不能修复形变；非等比拉伸会损坏比例。需要统一尺度时使用整组共同的比例，复核头身关系。 |
| 颜色忽深忽浅 | 按头发、虹膜、衣服等材质与基准比较。选择符合工具和用户授权的调色或重绘方法；纯调色时保护 alpha、轮廓和几何关系。逐帧独立滤镜容易放大不一致。 |
| 道具漂移 | 分开检查固定道具外轮廓和运动的手指。稳定笔记本不等于冻结敲击动作，以动作是否读得懂作为视觉标准。 |
| 有位移却缺乏表达 | 检查要求的语义是否可识别，再设计姿态、表情或辅助元素。机械左右移动通常不能替代等待、工作等意图。 |

关键特征逐帧核对，尤其眼睛、配饰和道具。修复后复查前次完成的内容，防止较旧素材覆盖新修订。

## 接缝与时序

检查动作内循环、末帧到首帧、待机到动作再回待机，以及方向组首尾和分段接缝。安静状态可共享落点基线；跳跃回到基准但保留高度，跑动保留步态。

预览从最终编码图集生成，不能仅使用高分辨率设计帧验收。设计稿帧数超过安装格式时，分别标注设计预览与安装版，保留设计稿而不声称已安装全部帧。

预览正常但应用中眨眼变慢、工作动作提前结束或注视不触发时，先核实当前应用的帧停留、循环和状态触发规则。用素材能实现的改善要实际交付；应用层限制单独说明。历史版本时长不是当前保证。

## 像素比较脚本

`../scripts/compare_atlas.py` 比较解码 RGBA 像素：报告变化行、像素数和输入哈希，授权行外有变化时返回非零。PNG 压缩字节变化但像素相同可以通过，尺寸不一致则失败。

输入必须可均分为指定网格。`--allow-rows` 为逗号分隔的 1 起始行号；省略时要求全部像素不变。授权一行允许该行内任意像素变化，更细范围需项目专用比较。脚本不判断动作质量、有效帧语义、透明格合规或实际时序。
