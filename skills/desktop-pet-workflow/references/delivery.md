# 便携交付与导入

## 数据边界

- 正式安装输入：当前配置和原始图集，预览、高清展示图与设计稿明确分开。
- 制作档案：解包保存源图、提示词、修订、可用脚本与有意义的 QA；不同档案维持独立相对路径，防止同路径不同版本相互覆盖。
- 环境状态：绝对机器路径、用户名、插件缓存位置、账号记录、已选中状态、部署标识、临时链接和上传会话不放进可移植内容。工具路径改为参数或环境变量，依赖写入说明。

保留来源署名、公开参考、可移植 slug、格式参数和有用的依赖版本。清理账号实例时不要删除作品身份或出处。图片如含元数据需单独检查；确需移除时记录字节变化，并比较解码像素。

历史配方写清用途、依赖、覆盖行为和未执行范围。语法检查不代表可一键重建。只复制可独立维护的自有脚本，插件辅助脚本通过对应插件获得。

## 打包

从跟踪的正式输入生成便携包，增加相对路径清单、大小、SHA-256 和导入说明。按 ZIP 实际内部路径生成文案，不假定所有旧包的根目录相同。

验证 CRC、重复和越界路径、清单、包内图集与正式输入的对应。说明和元数据变化会改变 ZIP 哈希，即使图集没变；同步更新网站哈希与大小。

生成目录加入忽略规则。按用户选择发布附件；采用“Git 保存解包素材，Release 只放便携包”时检查单文件限制并遵守划分。旧素材曾打成 ZIP 不构成强制使用 LFS 的理由。

## 导入或更新

同账号修复先确认原记录与目标内容，更新正确对象；跨账号使用目标环境新返回的身份。仅在用户要求启用时改变当前选择。已有明确授权继续执行，额外覆盖目标或扩展范围需要用户决策。

按当前工具规定验证、准备上传、传输和创建/更新，再回读名称、内容与选择状态。短期 URL 和上传会话属于一次操作，不能充当长期资产地址。未知结果先查询现状，确认失败再重试；同一失败持续出现时停止重复写入并报告具体缺失能力或错误。

服务器可能重编码 PNG：先比较文件哈希；不同时，在能取得双方图像的前提下比较尺寸、透明度和解码像素。下载失败只能报告元数据验证，不能推断云端图片与本地相同。原生目录、云端记录和桌面可见状态分别验证与描述。
