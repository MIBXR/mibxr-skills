# 便携交付与导入

## 数据边界

- 正式安装输入：当前配置和原始图集，预览、高清展示图与设计稿明确分开。
- 制作档案：保存实际采用的参考、高清原稿、提示词和创作说明。按[作品与版本发布](repository-and-release.md)确定保存范围；临时工具与检查报告留在任务工作区。
- 环境状态：机器路径、插件缓存、账号记录、已选中状态、内部部署标识、临时链接和上传会话留在目标环境。

保留来源署名、公开参考、可移植 slug 和格式参数。清理账号实例时保留作品身份与出处。图片如含需清理的元数据，保留画面内容。

用户明确要求可复现加工项目时，另行确定配方与依赖范围；一般作品交付无需附带加工程序。

## 打包

按用户选择的必要内容整理便携包，采用相对路径和简短说明。需要安装链接或下载校验值时从实际包取得，文案采用真实包内路径。

先核对目标协议真正规定的内容。sprite v2 的图集布局不自动规定 ZIP 目录或 `pet.json` schema；自定义交付元数据须明确标注，不称为通用原生安装器。源码中的作品版本与图集协议版本分别记录。

交付时核对包能否打开、是否包含正确图集与必要文件，排除重复或越界路径。说明和元数据变化也会改变 ZIP 哈希；本次涉及网站资源更新时，同步它实际使用的安装信息。网站是否更新或部署按本次范围决定。

采用“Git 保存解包素材，Release 提供便携包”时遵守该划分；临时生成文件留在工作区。旧素材曾打成 ZIP 不构成使用 LFS 的理由。

## 导入或更新

同账号修复先确认原记录与目标内容，更新正确对象；跨账号使用目标环境新返回的身份。仅在用户要求启用时改变当前选择。已有明确授权继续执行，额外覆盖目标或扩展范围需要用户决策。

按当前工具规定验证、准备上传、传输和创建/更新，再回读名称、内容与选择状态。短期 URL 和上传会话属于一次操作，不能充当长期资产地址。未知结果先查询现状，确认失败再重试；同一失败持续出现时停止重复写入并报告具体缺失能力或错误。

服务器可能重编码 PNG：先比较文件哈希；不同时，在能取得双方图像的前提下比较尺寸、透明度和解码像素。下载失败只能报告元数据验证，不能推断云端图片与本地相同。原生目录、云端记录和桌面可见状态分别验证与描述。
