# 便携交付与导入

用于成品打包、同账号更新、跨账号迁移或多环境同步。先确定本次要交付文件、导入应用，还是同时完成两者。

## 把三类内容分开

| 内容 | 保存在哪里 |
| --- | --- |
| 作品与制作资料：参考、来源、实际提示词、高清原稿 | 作品仓库中便于阅读和继续创作的位置。 |
| 正式成品：图集、必要元数据、预览和简明说明 | 解包文件由 Git 跟踪；按需提供便携 ZIP。 |
| 环境状态：本机路径、账号记录、当前启用项、内部部署标识、凭据和短期链接 | 在目标环境读取或配置，不随通用素材迁移。 |

保留公开出处、作者署名、稳定作品名称与格式参数。公开作者主页不等于私密身份；清理环境信息时按实际含义判断。图片元数据如包含本机信息，清理时保护图像内容。

## 最小包放什么

通常保留正式透明图集、名称与描述等必要元数据、逐动作 GIF 和简短使用说明。采用 sprite v2 时先读当前协议：图集布局不自动规定 ZIP 目录或 `pet.json` schema。自定义元数据写清项目约定，作品版本与协议版本分别表达。

预览覆盖全部实际动作。九种状态各一张 GIF、十六方向合为一张 GIF，是适用于对应格式的安排；用户有其他展示要求时按其选择。高清原稿、参考和提示词由作品目录保存。

解包后的正式文件适合普通 Git 跟踪，Release 提供便携包即可。无需因为素材曾经打成 ZIP 就引入 LFS；具体文件限制按目标托管服务判断。

## 根据实际包生成说明

先读取包内清单，确认是否有顶层目录，再写 README、元数据和导入文本中的相对路径。旧包的目录可能不同，不能凭另一款作品的路径推断。

包应能解压，图集与所标版本对应，必要文件齐全，路径无越界或重复。哈希只用于最终 ZIP 与正式图集的下载完整性判断；原稿、中间素材和制作记录全部保留，不为制作过程生成指纹。README 改动也会改变重新打包后的 ZIP 字节。

为 Git 历史修订 README 不意味着要重建已冻结的旧 Release。是否同步网站资源、发布新包或保留旧包，按本次用户范围决定。

## 更新正确的应用对象

同账号修复先找到原有宠物记录，更新该对象；新款作品另建记录。跨账号导入使用目标环境新返回的身份，来源账号 ID 不能当作可移植身份。

导入默认保持当前选择，只有用户要求启用或勾选启用时才切换。用户已授权的步骤继续执行，额外覆盖其他对象时再对齐范围。

存在云端记录与多个本地安装根时，从当前环境发现真实位置和接口，只同步本次指定目标。文件、账号列表与实际桌面显示是不同对象；删除一个本地目录不能证明账号记录已删除，也不能把内置项与自定义项混在一起操作。

按当前工具完成准备、上传与创建或更新。操作结果未知时先读回状态；连续同因失败且没有新信息时保留成品，报告具体卡点，避免重复创建记录。

## 完成条件

导入后在目标应用里看一次名称、素材和选择状态；能看到应用播放就看一眼。下载地址和上传会话属于当次操作，不作为长期备份。

交付文件路径或下载入口，说明更新了哪些对象、是否已启用。
