# 宠物仓库与 Release

用于整理已有宠物作品、建立可恢复源码或归档历史便携包。先读取实际文件与远端状态，再让用户决定会改变范围的选项：来源保存粒度、重建承诺、历史处理、预览集合、仓库可见性及是否部署网站。已有明确决策不重复询问。

## 终态资料集

推荐以当前已认可成品组织资料，而非按历次聊天工作目录堆叠：

- 每款宠物一个正式入口：元数据、无损图集、从正式图集生成的预览。
- 来源集：角色出处与署名、用户指定参考、实际采用的提示词和生成原图、必要加工参数。清单逐动作关联来源与结果；共享源文件可共用，避免复制到多个目录。
- 制作说明：解释当前成品的选择和加工方法。来源不明就标明，不按目录日期或文件名补造精确制作史。新指定的参考不能倒写成早先真实使用的原件。
- 维护入口：相对路径或显式参数、依赖版本、重建、检查和打包命令。生成输出与临时检查进入忽略目录。
- 当前 QA：记录被检查图集的哈希、执行命令、实际结果和未验证范围；可重复产生的几千张逐帧图片通常不必全部跟踪。
- 已有网站：保留源码、独立生成的高清原稿、媒体配方和下载关联。正式图集只保留一份源，网站副本在构建时产生。

采用“普通 Git 跟踪解包文件、Release 发布便携包”时，不再将整份材料 ZIP 放进 Git 或 Release。检查单文件限制；重复工作树字节不等于 Git 对象占用，因为相同 blob 会复用。

## 证明可重建

区分三个承诺：核验现有成品；从保存的生成原图/真实原始帧重建；重新调用生图服务。第三项有随机性，保存实际提示词、参考和可确认的调用参数，不保证重复生成同一图。

验证第二项时，在隔离目录只提供最小源集与处理工具，禁止把当前图集作为隐含种子。按真实的抽帧、共享缩放、配准、调色和行替换重放，逐行比较 RGBA；可同时比较编码哈希。检查依赖是否通过某个旧 atlas 间接借回了终态像素。

从成品裁帧再拼接只证明包装完整，不能证明原稿重建；像素差值补丁也不能替代缺失配方。当前不可复现时列出具体行、缺失输入或参数，请用户决定补齐、缩小承诺或修改作品，不能自行改成“成功”。

网站以正式图集提供几何参照是允许的显式依赖，但须与图集自身的独立来源重建分开。曾经由生图服务重绘的透明主图本身就是采用的生成原稿，不描述成确定性抠图。

## 最小分发包

包内容服从用户用途。一个可选约定是：统一元数据、正式 PNG、简明导入说明与署名、文件校验清单，以及用户选择的预览。对于当前 ChatGPT sprite v2，需要逐动作 GIF 时，从同包图集生成九种标准动作，并用一个按协议顺序串联十六个注视方向的 GIF 展示注视；其他应用或协议先核对其实际状态集合。不要混入旧设计帧、慢放复核版或模拟运行时版。

详细 QA、高清设计原稿、生成脚本和完整制作资料留在仓库。预览时长明确是展示约定或实测运行时；不能混称。通用包不包含原账号身份、启用状态、机器路径、短期链接或上传会话。

## 历史包和 Git 基线

历史 ZIP 先实际解包检查 CRC、结构、图集、隐私信息与哈希。包名的 v1.x 不代表 sprite v1。用图集字节/RGBA判断与当前成品的关系，不能把 ZIP 哈希不同当作作品变更。

用户选择统一重打包时，保留各版本图集原始字节，从各自图集生成所需预览；旧包本地留存，记录原 ZIP 校验值。不要连带公布其中的账号操作记录。归档标签可指向整理基线，但 Release 必须说明它承载历史成品，不代表当时存在对应源码提交；不伪造提交时间。

多宠物仓库可用一个当前正式 Release 集中提供最新版，旧版按宠物与版本分别归档；当前末版相同图集无需再复制一次。版本和图集的对应由清单表达，避免只依赖仓库级 latest 推断某只宠物的版本。

不可靠历史优先按用户选择建立终态基线，不重建推测的旧提交。改写主线、删除标签、替换已有 Release 是不同操作，确认它们各自是否已获授权。先验证本地 Git 与发布附件备份，推送前重新检查远端目标，使用带预期旧值的更新；未知发布结果先回读，不盲目重试。

主线重建不自动清除其他分支或标签可达的旧内容；检查拟保留的 refs。用于恢复的旧备份独立留在本地，不混入新的可移植资料集或上传。

发布验收需要新的干净克隆重建/核验、实际远端附件下载比对，以及可见性和 refs 回读。保留验证边界：源码重建通过不等于应用已安装或网站已部署。

跨平台恢复时固定依赖与文本换行，检查 Git 换行转换不会破坏来源 SHA；来源清单应显式更新，构建不应默默接受变更。清单中的图像指纹仍以原始编码字节和 RGBA 分别验证。
