# 完成审查

完成标准：用户逐项决定过找到的多余内容，同意删除的已删除，`scan_diff.py` 的 `flags` 清空。

## 步骤

1. 确定范围、计划和原样文件。
   - 范围：用户指定的提交区间。没有指定时，有未提交改动就扫描工作区相对 `HEAD` 的改动；否则扫描 `$(git merge-base HEAD <默认分支>)..HEAD`。
   - 计划：用户给的计划、任务说明或 issue；没有就用对话里约定的需求。从中列出允许改动的路径。
   - 原样复制进来的文件（配置备份、第三方代码）记下路径，内容不参与扫描。
2. 运行：

   ```bash
   python3 scripts/scan_diff.py --repo <仓库> [--range <a>..<b>] --files <允许的路径> [--verbatim <原样路径>]
   ```

   多个路径用逗号分隔，以 `/` 结尾表示目录。
3. 核对 `flags`：计划里没有明确要求的就是多余。
4. 判断 `review` 里的每一句：讲“是什么、怎么用”的保留；提醒、免责、进度或验证状态、改名与版本经过、在别处已经说过的内容，按 [规则](rules.md) 列为多余。然后把新增的文档通读一遍，词表漏掉的同类句子一并列出。
5. 看 diff 里脚本识别不了的结构问题：新增的抽象层、配置开关、独立服务、跨模块关联，兼容旧版本的分支，静默修正输入，重试包装，只有一个调用方的接口。
6. 交给用户一份清单：每项写 `文件:行` 或引原文，说明对应哪条规则，给出删除或改写后的内容。用户确认后再改，改完重新运行一次 `scan_diff.py`。
