# 诱因

配置里的这些写法会把 Agent 推向多做。判断时看它在实际任务中会产生什么行为，不看措辞本身。

## 全局指令与记忆

| 写法 | 诱导出的行为 | 改法 |
| --- | --- | --- |
| 汇报要求“区分已验证、推断和未验证”“说明遗留问题、限制或风险” | 回复里出现“这不代表……”“仍需确认……”，再漏进 README 和页面 | 改成“说明改了什么、结果如何；确有未完成的步骤时一句话说明” |
| 发布、打包或复制流程要求逐字节或哈希比对、核对多个来源一致 | 复制前后反复读、清单总哈希、发布记录哈希 | 改成“发布后打开线上页面确认一次可用” |
| 记忆里记着“事后重查哈希”“复核全部状态”一类流程 | 每次清理或发布都把多层核对当标准流程 | 删除这些条目 |
| 只禁止测试和哈希，没有提到文档措辞、架构和重复说明 | 测试少了，免责句、认证服务、跨库关联和重复强调照旧 | 写入全局指令块 |
| 规则全是禁令，没有说要怎么做 | Agent 以“以后代码可能会变”绕开禁令 | 写成要做什么，并在完成后用 `scan_diff.py` 检查 |

## 委派模板

给其他 Agent 写任务说明的模板、脚本或子代理定义里：

| 写法 | 诱导出的行为 | 改法 |
| --- | --- | --- |
| “必须运行验证命令”“汇报验证结果与遗留问题” | 每轮都跑全套测试，汇报“19/19 通过”，顺手补测试 | 验证命令按需列出；样式、文案、文档类任务默认不列 |
| 任务说明、日志、截图默认放在仓库里 | 过程产物进入提交 | 工作目录放在仓库外 |
| 说明文档的内容交给执行者自由撰写 | 文档里出现免责、过程和重复说明 | 由派发方写好每节要点 |

## 技能

会自动触发的技能里出现下列要求时，列给用户决定：

- 调试类技能要求先搭复现脚本或失败测试、修复后补回归测试，并强调“不计成本”“跳过阶段需说明理由”。
- 调研类技能要求把结果写成仓库里的 Markdown。
- 原型类技能要求把原型提交到分支，并在 issue 里留指向它的链接。
- 领域建模类技能要求在仓库里建术语表或决策记录（ADR）。
- 实现类技能要求先写测试再实现、每次跑完整测试套件。
- 设计类技能为可测性推动依赖注入和新的抽象层。

只在用户点名时运行的技能影响较小，列出即可。
