# Motion Atlas 影像与操作台参考

本库收录以时间线为载体的作品：作品掌握节奏，按时间线播放；即使可以交互，也是在时间线上分支。每个时间驱动的 Demo 都能逐帧渲染成视频。

用户往往说不清自己要什么。由你一步步剖析出需求，而不是把一堆看起来都还行的候选丢给用户挑。

## 第 0 步　确认载体

先确认最终形态是视频，或带时间轴、按时间线播放的操作台／展示台，即使它运行在浏览器里。难以判断时，设想逐帧导出为视频：核心价值仍在，才属于本 skill。判断以“谁掌握时间”为准，画幅不是判据：原作即使是固定画幅，复刻时也可以调整或拓展。
请求是网站或网页应用时，说明不属于本 skill 的载体后停下。请求同时包含两种载体时，只处理时间线作品的部分，并说明另一部分不在范围内。

## 第 1 步　读现场，写简报草稿

先读项目代码、现有页面或成片、品牌素材、用户原话，按 [references/brief-template.md](references/brief-template.md) 填写工作区的 `work/<任务名>/brief.md`，这是过程文件，不提交到项目仓库。
分成事实（读到的、用户说过的）、推断（写明依据）、未知（缺了会改变决定的信息）三栏，覆盖受众、目的、情绪基调、品牌与素材约束、喜恶参考、播放场景、时长、画幅、叙事与能量曲线、声音和交付形式。

## 第 2 步　只补问会改变决定的未知项

按 [references/intake.md](references/intake.md) 用体验语言提问，不用设计术语。每次一到两个问题，每个都附默认值；用户答“不知道”就采用默认值，记为推断，继续往下。

## 第 3 步　复述理解

用一段话说“我理解你要的是……”，请用户确认或纠正。这一步确认的是理解，不出方案。

## 第 4 步　检索收敛

按简报在库里找能成立的方向；检索命令、会话与 SHA 见 [references/cli.md](references/cli.md)。不满足简报的候选剔除，原因记进简报的“已排除”栏，不展示给用户。
资源库里的 skill 可以作为实现手段。选用时读取它的工作流和原文，并在简报中记录。
组合前读 [references/selection.md](references/selection.md)：`foundation` 是骨架，一个作品通常只有一个；`support` 承担区域职责；`accent` 是点睛，同一时刻不超过两个。检查 `pairsWellWith`、`conflicts` 和组合说明。

## 第 5 步　出对照

- **时机**：简报已经确认、方向基本定下之后。
- **数量**：2–3 个。
- **每个都是认真的方案**：都要满足简报，不放陪衬。
- **差异可以大**：结构、节奏、基调、表现形式都可以不同；但每个方案内部要一致，各自锚定库里不同的骨架（`foundation`）案例或巧思。
- **用真实内容做草样**，不用占位：每个方案出一条关键帧条（6–8 帧，标注时间点），加一段 2–3 秒的关键片段（低分辨率、低帧率即可）；横竖都要时各出一版。选定方向后再正式渲染完整片段。生成方法见 [references/preview.md](references/preview.md)。
- **每个方案附三行说明**：押注什么、牺牲什么、依据（案例或巧思 ID）。
- **模型给出倾向和理由**，但不替用户决定。
- **用户想组合时**：检查骨架是否唯一、点睛元素是否争抢注意力、触发或时间轴是否冲突；有冲突就说明取舍。

## 第 6 步　拆解反应

把用户的反应拆成具体元素：喜欢哪一部分、不喜欢哪一部分，允许跨方案组合。感受词按 [references/feel-map.md](references/feel-map.md) 落到参数上。
更新简报；一轮不满意时，先改简报再出下一轮，不随机再出三个。

## 第 7 步　定稿、取材、实现、验证

对最终采用的案例和巧思完整取材：`show ID --source`、`export ID --out NEW_DIR`（或 `--code-only`），用法见 [references/cli.md](references/cli.md)，Prompt 与组合细节见 [references/selection.md](references/selection.md)。
同一任务的材料取自同一会话 SHA。

实现时遵守：

- `render(t)` 的画面只依赖 `t`，不读墙上时钟或累加上一帧状态；随机数用 seed 并按 `t` 派生，异步资源让 render 返回 Promise，取帧等待完成。
- 可交互作品采用“事件列表推导状态 + 自动驾驶时间轴”：真实输入切到实时时钟，外部 `seek`／`play` 回到自动驾驶。
- 迁移时改作品本身，按真实内容适配，保留 `window.__motion` 协议：案例的作品代码在 `film/`；时间纯函数作品的时长、节拍标记与音轨在根 `index.html` 的 `MotionKit.mountFilm` 配置里，自有时钟的作品改 `film/` 内的配置；重放型巧思改 `index.html` 里 `MotionKit.replay` 的片段，拆分型巧思改顶部 `CONFIG`。
- 遵守 `prefers-reduced-motion`；声音默认关闭。
- 参考视频的取帧结果和渲染帧留在工作区，不提交。

按项目方式运行并按 [references/preview.md](references/preview.md) 渲染：看关键时刻的截帧和成片时长是否对上节拍，所需的横竖构图各看一遍；有声音的实际播放一遍，交互作品实际操作一遍真实输入与自动驾驶的切换。

交付时列出采用的案例／巧思 ID、各自职责和做了哪些适配，附选定方向的完整片段或约定的可交互作品。
小任务（换一段转场、调整片尾停留）跳过第 5 步。简报只写一两行，第 3 步可以和交付说明合并。

## 通用界面约束

- **普通网页文字**：桌面和移动端的正文、导航、标签、辅助信息、占位文字、提示及交互控件，最终渲染字号至少为 12px；考虑容器缩放和响应式样式。正文与主要操作按阅读需求选择合适的字号。确需更小字号时，先说明原因与适用范围并获得用户同意。
- **设计内容文字**：案例、巧思、嵌入 Demo、舞台及其画面内的文字（含 SVG／Canvas 图表和地图标签）按设计需要确定字号，可以小于 12px，无需因此单独征求同意。案例外的站点导航、筛选、说明和播放工具栏仍按普通网页文字处理。
- **SVG 图标**：导航、按钮、状态和其他功能图标使用标准 SVG 图标，优先复用项目已有的 SVG 图标组件；没有时选用一套成熟的 SVG 图标集，保持尺寸、线宽和视觉风格一致，按需引入。使用 SVG 图标表达搜索、关闭、菜单、方向等功能，不以 Unicode 字符、Emoji 或图标字体替代。正文中的标点、数学符号及作为内容的表情保留；品牌标志和内容插图按其素材规范处理。纯图标控件提供可访问名称，装饰图标不重复播报。
