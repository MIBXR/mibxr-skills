# 静态网站源码与交付

交付应能从仓库重新生成可运行网站，下载入口对应正确文件，并能在新环境恢复。静态 HTML/CSS/JavaScript 已足够的站点保留现有结构；任务确有需要时才引入框架或构建依赖。

## 核对版本

对比工作目录、Git HEAD、导出包和托管平台的当前版本。以内容和提交关系确定最新已认可结果，说明差异；导出 ZIP 的名字或日期不是最新状态的证明。

源码归档与线上部署分别界定。仅要求保存源码时完成本地构建及远端验证；需要发布时按已授权目标使用当前托管工具。

## 整理输入与配置

分开跟踪网站源码、原始媒体、产品下载输入和生成目录。媒体哈希或清单绑定展示内容与下载内容。高清展示图可以使用高分辨率源图，安装文件仍使用正式原件。

配置使用相对路径及显式 origin/base。机器绝对路径、托管账号项目 ID、缓存、认证和短期签名 URL 留在可移植源码之外；保留依赖声明、来源和必要的作品标识。

涉及旧 Git 历史、私有仓库或下载包清理时，先读 [迁移与发布](references/migration-and-release.md)。仅删除当前文件无法移除历史版本中的信息。

## 构建和浏览器验收

- 提供最少依赖的构建、核验及预览命令，输出写入明确的生成目录。下载包来自同一批跟踪输入，文件名、大小、校验值和包内路径从产物产生。
- 静态检查资源路径，再在实际浏览器测试受影响流程：操作结果、复制文本、下载内容和错误日志。构建产物变更后重新加载页面。
- 任务包含视觉或响应式调整时，覆盖对应的明暗主题、窄屏溢出、减少动画偏好和交互状态。截图不能代替交互验证。
- 安装文案准确说明环境能力、输入文件和用户选择。复制或下载成功仅证明入口可用；实际安装与启用需相应回读证据。

## 完成交付

把源码提交到已授权仓库，回读可见性和提交；从远端干净克隆后运行恢复命令。发布 Release 时重新下载附件核验哈希。发布网站时另核对保存版本、部署状态和线上主要流程；预览成功不能称为发布成功。

同一次远端操作结果不明时先查状态，避免重复创建。可恢复的上传失败保留已验证文件，按错误原因重试；持续失败时报告真实阻塞与已完成范围。

README 指向运行入口和恢复步骤。通用方法放技能，作品专属设计与修订依据留在作品仓库；交付时说明实际验证范围和残留限制。
