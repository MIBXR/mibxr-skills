# 静态网站源码与交付

交付完整源码与运行素材，使页面和下载入口可用。纯静态站点直接保存 HTML/CSS/JavaScript 与资源；实际使用框架时保留它必要的依赖和构建配置。

## 确定版本与范围

比较工作目录、提交、导出和已发布页面，找到用户认可的版本。文件名或日期不足以证明最新状态。源码整理和线上部署分别处理，仅要求保存时不额外部署。

网站与展示的宠物等作品可以独立保存、独立提交、分别更新。已有高清图、动画和下载包可以直接作为网站资源，无需强制从同仓库作品目录生成。

## 整理完整内容

先检查旧构建过程是否补入图片、下载或运行数据。删除加工程序前，把页面实际需要的文件带齐。机器路径、内部部署身份、认证和短期链接留在可移植源码之外，保留来源与作品标识。

涉及历史整理、私有仓库或固定下载链接时，读[迁移与发布](references/migration-and-release.md)。

## 核对受影响行为

- 对照实际文件检查资源与下载地址；包变化时同步页面使用的版本、包内路径与校验值。
- 用浏览器查看受影响的交互、安装文本和下载入口。视觉或响应式改动才扩大到对应主题、窄屏和动态效果检查。
- 使用页面 base URL 解析相对下载路径，兼容域名根目录与子目录。
- 安装文本说明输入和启用选择；下载成功不能等同于已安装。

这些是交付时的工作，不要求在作品仓库保存检查脚本或报告。

## 完成交付

向已授权仓库提交，回读提交与可见性。发布 Release 时确认附件，部署网站时确认线上版本及主要流程；预览不能代表部署完成。操作结果不明时先查询再重试。

作品展的 README 优先介绍作品、预览、来源和网站入口。任务确有需要时再提供操作教程；通用方法留在技能中。
