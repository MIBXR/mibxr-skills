# 网站迁移与发布

## 保存完整网站

已有纯静态 HTML/CSS/JS 可以直接作为交付目录，保留网站自身使用的图片、动画、运行数据和下载资源。使用框架的网站保留必要配置。清理旧构建程序前，识别并补齐它以前额外生成的文件。

网站与作品独立组织，可以保存作品资源副本，更新时替换自己的资源。不强制共享原稿、版本号或加工依赖。按真实资料记录网站自己的历史；缺失的网站版本不套用宠物版本补造。

README 展示作品与来源，提供网站入口。临时程序、报告与缓存留在工作区。

## 清理与历史

清除本机路径、内部账号/部署身份、凭据和临时链接，保留公开参考和作者署名。普通 API 字段名或作者主页路径不等于私密数据，应按语义判断。

一个版本一个提交、保留已有历史或从当前作品开始，由实际资料和用户目的决定。缺少证据不猜测补齐。主线改写、标签删除、Release 替换与可见性更改分别核对授权；已有明确决定则继续。

修改已发布历史前保留本地恢复副本，推送前确认远端未发生并发变更。待推送文件与 refs 都对应用户选定范围。

## 固定下载地址

网站可以保存固定名称的包，页面使用相对地址，如 `downloads/pet-name-portable.zip`。更新同名文件并同步安装信息后，页面地址保持稳定；拼接绝对安装链接时以页面 base URL 为准。

GitHub `releases/latest/download/<asset-name>` 选择仓库的最新一次发布；附件名不会触发按作品分别查找。私有附件需要访问权限。根据用户选择使用网站文件、指定版本 Release 或明确设计的查询方式，不擅自改变可见性或引入额外发布服务。

## 交付

检查受影响的页面资源、交互与实际下载。源码推送、Release 上传、网站部署分别回读结果。持续失败时保留已完成文件并说明具体剩余项；仅要求整理源码时不额外上线。
