# Web Atlas 网页设计参考

本库收录以网页为载体的设计：观看者自己滚动、点击和阅读，画面随屏幕宽度重排。页面里的动效、声音和内容组织都属于网页的一部分，一并收录。本技能从完整案例、独立巧思和内容素材取得源码、提示词与来源，结合当前产品实现页面。

用户往往说不清自己要什么。由你一步步剖析出需求，而不是把一堆看起来都还行的候选丢给用户挑。

## 第 0 步　确认载体

请求的最终形态应是网站或网页应用；视频，以及固定画幅、按时间线播放的操作台／展示台不属于本 skill 的载体，说明后停下。请求同时包含两种载体时，只处理网页部分，并说明另一部分不在范围内。

## 第 1 步　读现场，写简报草稿

先读项目代码、现有页面、品牌素材和用户原话，按 [简报模板](references/brief-template.md) 写入 `work/<任务名>/brief.md`。分成三栏：事实（读到的、用户说过的）、推断（根据事实推出的，并写明依据）、未知（缺了会改变决定的信息）。明确受众、目的、用户原话中的情绪基调、品牌与素材约束、喜欢和讨厌的参考，以及页面任务、内容量与密度、设备与断点、技术栈与已有组件、可访问性与减少动态要求。

扩展已有产品时，先查看同类页面与详情页的实际渲染、复用组件、设计 Tokens、响应式断点和交互模式，将现有风格与用户确认的约束作为实现基准。

## 第 2 步　只补问会改变决定的未知项

用体验语言提问，不用设计术语；问题清单见 `references/intake.md`。每次一到两个问题，每个都附默认值。用户答“不知道”就采用默认值，记为推断，继续往下。

## 第 3 步　复述理解

用一段话说“我理解你要的是……”，请用户确认或纠正。这一步确认的是理解，不出方案。

## 第 4 步　检索收敛

按简报在库里找能成立的方向。不满足简报的候选剔除，原因记进简报的“已排除”栏，不展示给用户。检索命令、目录浏览和会话用法见 [CLI](references/cli.md)，选材与组合规则见 [选择与组合](references/selection.md)。

## 第 5 步　出对照

- **时机**：简报已经确认、方向基本定下之后。
- **数量**：2–3 个。
- **每个都是认真的方案**：都要满足简报，不放陪衬。
- **差异可以大**：结构、节奏、基调、表现形式都可以不同；但每个方案内部要一致，各自锚定库里不同的骨架（`foundation`）案例或巧思。
- **用真实内容做草样**，不用占位：可滚动的页面草样，至少包括首屏和一个主要区段，桌面与窄屏各一张。
- **每个方案附三行说明**：押注什么、牺牲什么、依据（案例或巧思 ID）。
- **模型给出倾向和理由**，但不替用户决定。
- **用户想组合时**：检查骨架是否唯一、点睛元素是否争抢注意力、触发或时间轴是否冲突；有冲突就说明取舍。

## 第 6 步　拆解反应

把用户的反应拆成具体元素：喜欢哪一部分、不喜欢哪一部分，允许跨方案组合。感受词按 `references/feel-map.md` 的翻译表落到参数上。更新简报；一轮不满意时，先改简报再出下一轮，不是随机再出三个。

## 第 7 步　定稿、取材、实现、验证

对最终采用的案例、巧思、素材执行完整取材：`show ID --source`、`pattern-show ID --source`、`material-show ID --source`；需要可运行参考时用 `export ID --out NEW_DIRECTORY`、`pattern-export ID --out NEW_DIRECTORY`、`material-export ID --out NEW_DIRECTORY`，详见 [CLI](references/cli.md)。

按 [选择与组合](references/selection.md) 核对来源、证据等级、网页说明、许可与实现适配，再用真实内容实现。材料保持同一会话 SHA，刷新后重新确认方案与资料。

- 按当前项目方式构建和运行，检查真实内容下的桌面主要页面、窄屏布局、关键交互、键盘操作、减少动态、可读性和资源加载；对照选中案例检查设计依据是否落实。
- 动效实测起始、过程、完成与回程；声音实测触发、静音、重复播放、手机入口和后台行为，记录未验证项及本地适配边界。
- 在桌面和窄屏实际渲染中核验普通网页文字的计算字号及容器缩放，覆盖提示、占位文字和交互控件；案例、巧思及画面内文字按设计要求验收，不因小于 12px 判为不合格。静态 CSS 搜索只能辅助检查，不能替代渲染验证。
- 检查功能图标的 SVG 来源、风格一致性和纯图标控件的可访问名称。
- 扩展已有产品时，在相同桌面与窄屏视口宽度下，对照兄弟页面检查网格列数、卡片结构、字体层级、标签、悬停与焦点状态、导航和详情页模式；确认一致性及用户约束落实，保留的差异应有具体功能依据。

交付时列出最终案例／巧思／素材 ID、上游 SHA、各自职责、做了哪些适配、实际验证的页面与状态、哪些没验证；当前项目的运行结果决定交付是否完成。

小任务（改一个按钮反馈、换一段转场）跳过第 5 步。简报只写一两行，第 3 步可以和交付说明合并。

## 通用界面约束

选择方案和实现网站时应用以下约束，并区分普通网页界面与供展示或复现的设计内容。

- **普通网页文字**：桌面和移动端的正文、导航、标签、辅助信息、占位文字、提示及交互控件，最终渲染字号至少为 12px；考虑容器缩放和响应式样式。正文与主要操作按阅读需求选择合适的字号。确需更小字号时，先说明原因与适用范围并获得用户同意。
- **设计内容文字**：案例、巧思、嵌入 Demo、舞台及其画面内的文字（含 SVG／Canvas 图表和地图标签）按设计需要确定字号，可以小于 12px，无需因此单独征求同意。案例外的站点导航、筛选、说明和播放工具栏仍按普通网页文字处理。
- **SVG 图标**：导航、按钮、状态和其他功能图标使用标准 SVG 图标，优先复用项目已有的 SVG 图标组件；没有时选用一套成熟的 SVG 图标集，保持尺寸、线宽和视觉风格一致，按需引入。使用 SVG 图标表达搜索、关闭、菜单、方向等功能，不以 Unicode 字符、Emoji 或图标字体替代。正文中的标点、数学符号及作为内容的表情保留；品牌标志和内容插图按其素材规范处理。纯图标控件提供可访问名称，装饰图标不重复播报。
